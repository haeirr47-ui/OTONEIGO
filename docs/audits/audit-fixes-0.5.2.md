# 0.5.2 启动、完整性与坏行恢复审计

2026-11-02。仅处理本轮匿名客户端缺陷；没有登录、安装器执行、系统网络变更或用户导入/导出/备份恢复功能。来源仍是合资格缓存优先、按出口预选网易云、失败后才允许已启用且限速的GD。

## 逐项结论

| 报告项 | 核实与最终处理 |
| --- | --- |
| 启动同步读取/完整解码全部封面 | 确认，禁用时原来也发生。New现在只读有界manifest及文件属性，不读封面/歌词payload，不做全量digest或像素解码。首次实际使用才按key合并验证，最多四个工作槽，锁外执行；热读仍核对内容digest。启动仍随索引条目数增长，不承诺完全O(1)或完全不碰文件系统。 |
| 大音频命中前整文件hash | 确认。采用分块摘要替代“先发未经验证字节、后台补查”：新下载在完整校验提交时同时保存1MiB块摘要；读取只从该次hash匹配的同一缓冲区复制。开播结构检查只触及前缀/尾部相关块，HTTP先校验请求首块再发状态和音频；后续逐块校验。 |
| 旧缓存的兼容 | 旧记录没有块摘要，首次仍需完整SHA256/Inspect并在同一读取过程补建索引，成功持久化后下一次重启走分块路径。写盘失败可能需要下次再升级，不声称所有旧缓存第一次就无全量开销。 |
| Lookup解锁期间继续range map | 确认候选集合和替换身份存在竞态，不是已复现的map并发崩溃。改为锁内取得候选指针快照，校验前后重新检查身份/状态，删除也不能误删替代条目。 |
| 失败面板仍显示加载中 | 确认。未ready且没有libraryError才显示初始化加载文案；失败显示重试，不再同时永久转圈。初始化在分页读取及可能的坏行隔离之后取得完整收藏ID，避免保留已隔离歌曲的旧爱心状态。 |
| GD预算耗尽覆盖明确直连原因 | 确认。已有EMPTY_URL、NO_AUDIO_URL、地域/超时等明确结果时保留主原因；只有没有明确主结论时才用GD预算错误。GD阶段诊断仍独立记录，调用者取消和总截止时间优先级不变。 |
| 一条坏行阻止启动 | 确认旧合同会如此。schema7在事务内保留异常原值并隔离，设置回落默认并显示明确提示；健康资料继续工作。旧schema升级可一次性扫描相关记录；已经schema7的启动只检查单行设置，收藏/历史在实际读取时按100行批次恢复，填满健康结果页，不每次全扫长期历史。 |
| 持久化未知字段 | 本地设置/收藏/历史允许未知成员的已知投影读取，仍检查UTF8、大小、尾随JSON、已知字段类型/范围及身份。设置保存递归合并并规范化已知字段的大小写别名，保留未知后代；冲突的未知值明确拒写。含未知成员的已有收藏更新也明确拒写，不静默丢字段；历史幂等插入不覆盖原文。队列和歌单既有协议不在本轮改写。 |
| 日志轮转失败永久静默 | 确认。只有显式Close才终止记录器。故障期间有界丢弃/计数，后续Record每秒最多重试一次；成功后恢复记录。Status返回固定错误码及丢失计数，Close保留已发生I/O失败的脱敏错误；不截断或无限增大日志来掩盖轮转失败。 |

分块读取只证明**实际交付的块**完整；尚未请求的中间块在真正读取时才检查。首个请求块损坏返回410，中途损坏中断响应并使后续请求410，排除持久化且等待活动使用释放后清理。全文件SHA仍用于完整下载提交及旧记录升级。块数最多512，manifest读取/保存上限调整为128MiB，超限保存保留之前的有效清单；没有把完整性检查删掉来提速。

## 数据保护与可见性

`local_record_quarantine`保存来源表、原rowid、固定原因及原SQL列值；NULL、BLOB、超长值不截断、不转为日志。归档和从活动表移除在同一事务，失败一起回滚。桥接只提供收藏/历史计数和设置恢复标志，界面说明原始异常记录已保留，日志只写固定storage/LOCAL_RECORDS_QUARANTINED。物理数据库/SQL故障及高于7的未来schema仍拒绝打开，不能用默认空库覆盖。

自动修复保留原文，显式用户删除尊重删除意图：“清空历史”在一个事务里清除活动历史和隔离历史，保留收藏/设置隔离记录。没有增加恢复按钮或用户备份产品功能。设置正常GetSettings仍是纯读，异常设置只在Open的恢复事务里处理。
