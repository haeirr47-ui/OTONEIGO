# 0.5.3 缓存队列、恢复提示与写入审计

2026-11-02。schema仍为7；不新增账号、安装器、系统网络变更、导入导出或备份恢复功能。缓存优先、按出口预选网易云、失败后才GD的规则和限速不变。

## 核实与修复

| 报告项 | 结论与最终行为 |
| --- | --- |
| 懒验证与下载共用四槽 | 确认。验证使用独立两槽，封面网络下载仍四槽、歌词两槽。四个RoundTrip被阻塞时，缓存首验Cover和HTTP两条路径原来都超500ms；独立池后约30ms内完成，网络仍四忙。保留首验合并、取消、清空代次及损坏文件保护。 |
| 恢复提示无法关闭、永久红条 | 确认。改为中性色状态提示，增加“知道了”；只在当前主界面会话的内存中记住已确认状态签名，不删除或改写隔离记录。同签名不重复显示，不同签名可重新显示；不是永久忽略或按天删除记录。重启开启新会话。 |
| Lookup命中但Prepare失效就整次失败 | 确认，原回归返回AUDIO_CACHE_FAILED且网络尝试0。新增ResolvePrepared，让缓存接纳处于原配置/网络代次和原截止时间内；缓存候选无法接纳时仅一次跳过缓存重解析，不再次进入接纳循环。缓存记录不保存可复用的原签名地址，因此重新按当前正常规则获取；本来就有完整可信网络地址时，缓存故障不丢弃该地址。取消/配置失效不重试，不延长总预算，不为完整可播网易云流调用GD。 |
| 分块清单每5秒整份重写 | 确认。访问时间改写有界原子recency.json，不包含Chunks；结构manifest保留内容/质量/块摘要和访问基线。用Generation与BaseAccess绑定替换身份，旧或损坏的可选sidecar不会复活/破坏音频。结构变化、旧索引升级及启动结构保存仍需完整manifest，不宣称零大写入。 |
| 5秒永久恢复检查及全局缓存统计 | 确认。恢复状态立即检查，完成后30秒再查，无重叠；不停止所有检查，以便发现后续懒隔离。缓存统计从全局pollRegion移入设置页，进入立即读取、完成后30秒，离开停止。旧挂载未完成请求被合并等待，活动性与请求版本保护阻止旧成功/失败覆盖新统计；手动清理/保存后的刷新继续工作。地区5秒策略不变，读取后端内存状态，不是每5秒定位公网或查SQL。 |

recency是相对最近结构保存基线的累计访问增量，可能随访问过的曲目数增长，不承诺每次恒为172字节；上限65,536条/16MiB。每次仍原子写入并fsync小型sidecar，后台至多每5秒重试，Close可额外flush。结构保存失败设置structuralDirty，由reaper和Close补写，避免完成的缓存重启时成为孤儿。原有manifest的LastAccess兼容读取，Generation是可选内部标识，不是账户或媒体授权token。

## 回归与独立复查

- 独立验证池：新增两条占满真实网络worker的确定性红→绿回归；原有首验/两槽上限、取消、旧代次、Windows文件占用与替换失败测试保留。
- 访问落盘：约20GiB的合成分块索引，旧Close重写1,777,100字节；新结构清单1,826,300字节的内容/mtime在实际Lookup→reaper→Lookup→Close全过程不变，本次只写172字节recency。不是实际存了20GiB媒体，也不是所有工作负载固定缩减倍数。
- 缓存竞态：真实Prepare接收失效缓存候选模型，原先失败；现在一次新网络尝试、一次缓存接纳、原预算不变。另测取消、策略失效不发新请求、不可信URL拒绝、缓存不可用时保留完整可信地址；兼容unknown保持旧语义，不把地址可信性误等同于status=full。
- 存储失败：阻止manifest.tmp写入直到真实合成下载完成，解除阻止后Close或真实reaper补写，重启仍保留缓存；失败重试不因访问时间dirty而突破5秒限频。损坏/超限/旧代次sidecar只丢访问增量，不使音频失效。
- 设置页请求：实际PlayerStore的退出/重进、旧结果后返、旧异常及新手动刷新竞态有红→绿回归；独立复查还验证连续三次挂载/退出，停用后的结果不发布、不堆积。

复查修复了新实现的两个回归：最终地址检查错误要求full而拒绝原有unknown兼容结果；拆出recency后结构写失败未补存。原生验收另发现提示层继承pointer-events:none导致“知道了”点不到，已改为该提示卡片接收鼠标，并重跑真实点击。其余源选择、单队列/单Audio、账号禁用与数据隐私边界未改。
