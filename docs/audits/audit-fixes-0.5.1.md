# 0.5.1 缓存与状态审计：核实、修复和复验

2026-11-02。范围为当前匿名 Windows 客户端；未改来源优先级，没有登录、安装器构建/运行或系统网络设置修改。全部代码仍未暂存、提交或推送。

## 逐项结论

| 报告项 | 核实与处理 |
| --- | --- |
| 封面重复解码、全局锁 | 确认。原 HTTP 命中有 **2 次完整 Decode + 2 次 DecodeConfig**，不是4次完整解码。下载/启动载入完整验证一次，保留有界、仅内存的摘要/MIME 记录；热读在锁外读取并计算 SHA256，复用 MIME，不再重复解码。 |
| no-store 导致每次渲染/滚动请求 | 推断过强。no-store 不等于 React 每次 render 必然重发图片请求；没有复现“一屏50封面”的具体滚动样本。保留 no-store，避免同一源散列 URL 内容更新/清理后展示过时缓存，未盲目改为 immutable。 |
| 每次音频命中重写 manifest/fsync | 确认。LastAccess 改为内存 dirty，后台最多每5秒合并保存，正常 Close 尝试 flush；新缓存内容提交、失效和清理继续同步持久化。强杀至多丢最近访问次序，不将内容提交变为延迟保存。空闲 prune 不再重写文件。 |
| 锁内整文件 SHA256/Inspect | 确认。改为每条目单飞、锁外 stat/hash/Inspect，校验期间 pin，返回时重查条目身份/清空代次/资格；并发 Stats、Clear 不再等完整文件读取。自身冷命中仍需实际校验。 |
| 每64KiB重复 Open/Close | 确认。每个渐进 HTTP 响应持有并复用读取句柄；Windows 使用 FILE_SHARE_DELETE，允许下载完成重命名，pin 保护活动文件。 |
| libraryReady 初始失败后无法恢复 | 确认。重试重新读取完整收藏 ID、收藏首屏及历史首屏；所有成功才开放写入，并合并并发重试，不写默认空库。 |
| 收藏/历史写操作跳回第一页和清空 | 确认。保留当前筛选、页码及已有列表，写入后刷新当前游标页；删除造成空页时退回有效页。自动记录历史不再让第5页跳页。 |
| seek 每次提交 SQLite | 确认。定位和界面立即更新，250ms trailing 合并持久化；暂停、关闭、换曲及其他队列提交处理待保存位置，沿用串行 revision/CAS。 |
| GD 三档必然超时 | 不成立：三次最早可在0/6/12秒派发，17秒可成功第三档。但重复资料查询、预算不足仍排队及错误原因丢失确有问题，已修复，见下节。 |
| GetSettings 读路径回写、高级偏好丢失 | 确认。读取仅返回按当前资格归一化的视图，不写盘/不触发回调；启动保留原始质量偏好。匿名修改音量/窗口等保留休眠的高级偏好，实际播放仍封顶320；可信会员可明确修改该偏好。没有新增登录或会员授权。 |
| SettingsChanged 持设置锁执行 | 确认。提交在锁内排队，锁外单一通知 drain 合并到最新完整快照，支持回调重读/重入写设置，不以简单异步回调造成旧设置覆盖新值。 |
| 安装器固定标题检测 | 确认潜伏问题。源码改为对精确目标 EXE 使用 GENERIC_WRITE/OPEN_EXISTING 检查，失败即中止，不依赖标题，不截断或写入文件。仅静态核对 NSIS；原生验证 Windows 对运行映像拒绝写打开的同一机制，未编译或执行安装器。不能称安装/升级验收。 |
| MP3 16KiB ID3、ID3v1 尾标签 | 确认结构边界。接受有界前缀内可验证的较大 ID3v2/footer；Inspect 在最多256KiB前缀外额外读取128字节尾标签，严格区分真实ID3v1和伪造尾部，保持 Xing/VBRI 字节数检查。不是任意标签大小/全部 MP3 格式承诺。 |
| desktopProjection frozen 不复位 | 当前不能构成报告所述恢复故障。CloseGate 的真实退出已锁定并有兜底，不存在“取消退出后继续使用”的分支；关闭到托盘不会进入该终态。保留关闭冻结，增加 epoch 变化不能复活终态的回归。 |
| 数字前缀公网域名误判内网 | 确认。用 URL 解析后的完整 IPv4 字面量判断；10.example.com 不再误拒，私有字面地址及受控 loopback 限制保留，未放宽 Go CDN 白名单。 |
| 托盘私有布局失败静默退化 | 依赖仍存在，已补固定脱敏 desktop/TRAY_UNAVAILABLE 诊断，按不可用状态去重并在恢复后重新观察下一次故障；不实际重启 Shell，不改变不可用时保留可访问窗口的行为。 |

## GD 的最终预算契约

保持至少6秒 API间隔、17/31秒 GD阶段、26/40秒总预算和调用者更短截止时间。各档复用同ID短期已验证资料（30秒、最多128项、失效代次清理）；资料请求上限3秒。派发前判断限流等待后至少剩4秒可用预算，不够则明确返回 GD_BUDGET_EXHAUSTED，不消耗 API槽位，也不当成服务故障冷却。

4秒是准入下限，**不是**容纳 API与探测各自最坏3秒的保证。共享 API维持独立3秒上限，不因首个短调用者缩短后来长调用者的请求；每个调用者仍独立取消，最后等待者离开才取消共享任务。慢请求/限流竞争下可以用尽总预算，不承诺每次三档全走完。错误使用固定中文提示和固定诊断码，不显示原始载荷。

真实时钟、受控 transport 的回归验证320缺失→等6秒→192缺失→等6秒→128成功，仍在17秒调用者预算内，资料只查一次。另覆盖短调用者先派发、长调用者加入、首位取消后长调用者成功且只有一次 API。真实 GD 单次线上探测另取得33894312/full/exhigh/MP3/320000bit/s/267258ms/10691439字节；不将受控三档测试冒充上游三档实测。
