# Netease adapter and bounded resolver (P0)

> Current implementation: 2026-11-02 / 0.5.3. The dated 2026-10-31 observations below are historical evidence, not acceptance of the integrated application path.

`internal/catalog` provides search, song metadata, lyrics and direct stream resolution using a bounded, anonymous standard-library HTTP client. It contains no account state, cookie jar, GD, alternative catalog, upstream application queue, or UNM module. The separate `internal/stream` resolver orchestrates the ordinary request, bounded compatibility and independently gated GD adapter. Redirects are rejected and returned media URLs must use a subdomain of `music.126.net`; HTTP is upgraded to HTTPS. Stream URLs exist only in return values, never queue snapshots or probe output. Cover references accept only HTTPS `music.126.net` subdomains without credentials, query parameters or fragments.

IDs decode as `json.Number` and are copied to string DTO fields without floating point conversion. Queue/library metadata and provider responses are bounded. Provider errors expose fixed labels rather than response bodies or request URLs. Requests have a 12 second deadline and use Wails-propagated cancellation contexts.

`full` means the provider returned `freeTrialInfo: null` and a positive playback duration; it is provider metadata, not proof of complete native playback. Non-null trial information is `trial`; missing completeness evidence is `unknown`. Empty links are unavailable or explicitly unauthorized. Quality and format are reported from returned metadata rather than inferred from the requested option. Native WebView2 playback, region/rights behavior and complete duration still need independent acceptance.

The current compatibility allowlist is exactly POST to `https://music.163.com/weapi/song/enhance/player/url/v1`, with no query/userinfo. Only that request receives the fixed, versioned `RegionHintVersion` protocol hint (`X-Real-IP`); it is a best-effort experiment, not proof of location or rights. Search, metadata, lyrics, Cloudflare detection, GD and any future QR/auth operations do not use this rewrite. TLS verification remains enabled. CDN hostname rewriting and `no-cache` are not implemented.

Eligible verified local bytes remain first. Before network playback, the resolver selects a route using the current setting and observed region: `auto+CN` uses ordinary Netease only; `auto+overseas` and `always` use the bounded compatibility header from the first request at every attempted quality, with no ordinary preflight; `off` uses ordinary Netease only. `auto+unknown`, including detection failure, retains ordinary-first then eligible compatibility fallback. Only failure of the selected Netease quality ladder allows enabled/rate-limited same-ID GD. Any complete playable Netease result returns immediately, including an honest lower bitrate; GD is never used to chase higher quality or replace a working stream.

The shared deadline remains 26 seconds for anonymous/nonmembers or 40 seconds for verified members: ordinary at most 4 seconds, compatibility at most 5 seconds, GD at most 17/31 seconds. An unselected ordinary phase is not issued and its unused budget does not extend another phase. Waiting, quality fallback, probing and media startup consume the same finite budget. Trial/unauthorized and explicit player login requirements block subsequent header rewriting in the ordinary-first branch; direct compatibility does not require that preflight. Cancellation, rate-limit, invalid ID/quality and invalid/untrusted responses stop further fallback. Compatibility has a three-failure, one-minute cooldown. A direct-compatibility route in cooldown never retries ordinary Netease: it may use eligible enabled GD or return `COMPATIBILITY_COOLDOWN`. Generation invalidation cancels pending results; no direct-stream URL cache exists. Failed compatibility does not establish `REGION_RESTRICTED`.

This supersedes the former universally ordinary-first policy. Dated historical observations below retain their original conditions. The existing 0.4 native resource/query, offline and crash runs used the former routing policy; actual HTTP routing and native startup under this correction have now passed separately in `output/playwright/native-egress04-report.json`; see the [P0 record](p0-validation.md). This new run did not wait for whole-song natural completion.

`internal/gd` only requests `types=url&source=netease` for the same string song ID, obtains Netease metadata, validates HTTPS Netease media hosts/redirects and bounded audioinfo structural MP3/FLAC/WAV evidence plus Content-Range/length. It derives bitrate and duration from the supported structural evidence and rejects a duration difference above max(2 seconds, 2 percent). Unsupported or insufficient evidence fails closed; neither the requested `br` nor a matching duration establishes recording identity, complete native playback or high-resolution fidelity. Requests merge by ID/quality, dispatch at least six seconds apart, keep successful results in memory for at most 30 seconds and cool down after three failures. Network/policy invalidation clears transient state. Production `gdReleaseValidated = true` now exposes the optional fallback, while the user setting remains false by default. The release decision is limited to the independently tested same-ID MP3 sample; account capability remains false. Every `full` result and every GD result must also pass duration validation against the same actual Audio element metadata at startup.

Fixed-schema diagnostics record only selected stage/status/quality/error metadata, not provider bodies or signed addresses. See [architecture](architecture.md), [storage](storage.md) and the [P0 matrix](overseas-compatibility-p0.md) for the current contract and independent acceptance requirements.

The WEAPI constants and endpoint/parameter contracts were adapted from the local vendored copy of the MIT API project `go-musicfox/netease-music`: `go-musicfox-master/vendor/modules.txt` identifies it as **v1.6.0**. Inspected files were `util/cryto.go`, `service/search_service.go`, `service/lyric_service.go`, and `service/song_url_v1_service.go`; the later diagnostic also inspected `util/request.go` and `service/song_url_service.go`. The implementation plan names commit `912f2cf2b8bf772c804c6cd4b4f31f11773c7b93`, but that commit has not been established as the exact byte source of this vendored copy. Cryptographic primitives were independently implemented with Go stdlib; no OpenSSL dependency, request wrapper, GPL go-musicfox application code or UNM code was copied. The reference library itself is not a dependency.

## Media byte cache and native format boundary (since 0.3.0)

The same-process `internal/mediacache` loopback server serves only token-bound media GET/HEAD/Range requests to the existing AudioEngine. It is not a local business API or another process. Only validated trusted HTTPS Netease media may enter it. Progressive `.part` playback does not establish a complete cache entry: length, MP3/FLAC/WAV structure, duration and SHA-256 must pass before commit. Cached provenance retains actual quality, provider and format, including a lower-grade candidate selected by the network fallback. Signed URLs and lease tokens are never persisted.

The cache is enabled by default with a 20 GiB limit, LRU, active pins, deferred clear and free-space checks. High-grade media requires a matching verified account/member scope; accounts remain disabled in the production entry point. The GD adapter uses audioinfo structural checks for MP3/FLAC/WAV; the release evidence remains actual MP3 only. Format-checker or cache FLAC/WAV support does not establish real member/high-resolution playback. Controlled, self-generated 3-second FLAC/WAV fixtures each naturally ended in the actual native WebView2, with resolver/media interception; this establishes decoder behavior only, not real member playback or cache transport. Live CDN MP3 progressive/cache-warm/Range evidence is recorded separately. The historical 0.3.0 run passed actual WinRT Pause/Play/SkipNext, process-only offline cached startup/seek, final build and portable ZIP/hash verification. These dated results do not establish acceptance of 0.4.0; see the [P0 record](p0-validation.md).

## Public artwork and lyric cache (0.4.0)

`internal/resourcecache` caches public lyrics and trusted Netease artwork independently of the audio resolver. It introduces no credentials, alternate catalog or dependency. Default-on resources share 1 GiB (configurable 64 MiB..1 TiB); the separate audio cache remains 20 GiB by default. Artwork requests reject redirects and credentials, preserve HTTPS validation, and accept only existing trusted cover references. JPEG/PNG/GIF require complete decoding within the 4 MiB and dimension/pixel bounds; WebP/AVIF bypass the local cache and retain the trusted original reference. Only the internal outgoing display-art fetch adds fixed `param=1024y1024` after the original no-query reference passes validation. Caller-supplied query strings remain rejected, and cache identity, snapshots and fallback retain the original canonical reference. Bytes determine the decoded format even if HTTP MIME disagrees. Persisted snapshots retain that reference; the manifest stores opaque hashes and validation metadata without URLs.

Cached artwork is delivered as `/artwork/<hash>` through the existing Wails same-origin asset handler using verified bytes, with no new listener. `Cache-Control: no-store` prevents an additional browser HTTP cache copy; the audio channel uses the same policy. This response policy is distinct from the still-deferred upstream CDN/no-cache compatibility experiment.

Lyrics are bounded to 1 MiB JSON. Valid cached lyrics return immediately, refresh asynchronously after seven days, and remain usable if refresh fails; refresh retry is throttled for five minutes. Empty lyrics are not permanently cached. Four artwork and two lyric workers share a bounded 64-job admission pool; artwork admission stops at 60 total jobs to reserve capacity for lyrics. Cache disable/clear, corruption recovery, LRU and lifecycle locking do not change playback entitlement. Current-version native online/offline resources, actual process-kill recovery and extracted production portable-update checks have passed in bounded cases recorded in the [P0 record](p0-validation.md). These resource/durability runs used the previous routing policy and do not serve as routing evidence.

The independent new-routing native run observed real TH/overseas in auto mode, without simulated region or network interception: sample 33894312 used ordinary/compatible/GD counts 0/1/0, actual 320000 bit/s, 1435 ms startup and 267.245714-second media metadata; the GD fallback sample used 0/3/1, 2209 ms startup and 227.731917-second metadata. Both used one Audio element. This proves direct-compatible startup and bounded GD fallback for those samples, not whole-song natural completion or other regions/accounts/formats. CN, real VPN/exit-node comparisons, authentication and real member media remain unverified/deferred.

A real same-canonical artwork reference yielded an original 6,050,435-byte PNG; the internal fixed-size request yielded a valid 1,863,113-byte 1024-square PNG despite image/jpg HTTP MIME, without changing the snapshot reference. A real same-hash 404 after clear was recovered by mounting a new image element. Process-only offline resources returned in 308 ms and cached audio started in 184 ms with zero new audio API requests. These are bounded observations, not performance guarantees.


## 0.5.1 bounded fallback and cache work

GD still starts only after the selected Netease path fails, with at least six seconds between API dispatches. The 17/31-second GD and 26/40-second total budgets remain finite. Verified same-ID duration metadata is reused for at most 30 seconds (128 entries), invalidated with the client generation. Rate admission requires at least four useful seconds after waiting; this is a floor, not a guarantee of both worst-case three-second API and probe durations. Shared API work retains its own three-second cap so a later long-budget caller does not inherit the first short caller's timeout. Budget exhaustion does not consume an unused slot or count as an upstream outage. A controlled real-clock test reaches the 128-kbps third tier; a separate live same-ID 320-kbps probe is recorded in the [audit report](audit-fixes-0.5.1.md).

Full audio structural inspection retains a bounded 256-KiB prefix and now reads a 128-byte MP3 trailer separately; large bounded ID3v2/footer and verified ID3v1 cases are covered by fixtures, without relaxing Xing/VBRI byte counts. The two existing real cached MP3 samples have small ID3 tags and no ID3v1; they do not establish live coverage for those edge cases. Cold hash/inspection is single-flight outside the cache state lock; access-time persistence is batched while content commit/invalidation remains synchronous. No new dependency or account entitlement is introduced.


## 0.5.2 delivered-byte integrity and failure precedence

New completed media cache records carry 1-MiB chunk SHA-256 indexes derived in the full transfer-validation pass. Indexed reads inspect bounded authenticated prefix/tail data and copy only from the exact verified chunk buffer before delivery. A bad initial range returns 410; later corruption aborts the response and invalidates later requests. Unrequested regions are checked when requested, not before first byte. Legacy records retain one complete hash/structural validation to build a persistable index; persistence failure may require another legacy scan. Current account/quality scope is unchanged; this does not grant membership or validate new formats.

A GD_BUDGET_EXHAUSTED result no longer replaces a concrete Netease failure code/error. With no concrete primary conclusion, the bounded fallback error may still surface; caller cancellation and total deadline keep priority. Resource cache initialization now reads metadata/file attributes only, with full image validation on first use. Previous-version startup full-validation statements above are historical. See the [0.5.2 audit](audit-fixes-0.5.2.md) for measured versus native evidence and limits.


## 0.5.3 cache-admission recovery

Resolution and optional cache admission now share the original caller deadline and policy/network lifetime. If a returned cached candidate disappears before admission, one retry skips cache lookup/admission and obtains a new address through the existing Netease/compatibility/GD priority. Cancellation or invalidation prevents that retry; no budget reset or loop is added. A complete trusted provider address survives optional cache failure, while URL trust checks preserve the pre-existing unknown compatibility and entitlement result semantics. No signed source address is persisted to enable this behavior.

Access times use a bounded generation/base-bound recency sidecar; immutable chunk metadata stays in structural manifest commits. Structural failure retries remain durable, and original privacy/entitlement/identity checks remain. See the [0.5.3 audit](audit-fixes-0.5.3.md); this patch adds no upstream quota-consuming acceptance campaign.
